** Two code changes (both correct & necessary), pochoir core
- arrays.py: rgi(..., fill_value=...) optional (scipy bounds_error=False).
- __main__.py induce_pixel: rgi(..., fill_value=0.0).  REQUIRED for the

** Findings / limitations (why 1e-6 is not reached)
1. response_44_v2a_full is an INDEPENDENT calc (Jiangmei/tred), not pochoir =>
   1e-6 agreement between two different codes is not physically achievable.
2. STRUCTURAL peak gap: pochoir near-pad dQ/dt peak is ~0.45x tred in EVERY
   config (deep z148, shallow z28, shallow z39.5).  tred's pixel-edge Ramo spike
   (~4.9) is much sharper than pochoir's broad bump (~0.8) -- a genuine
   method/resolution difference, independent of epsilon or domain depth.
3. SHALLOW-DOMAIN cost: the depth-400 far boundary (W=0 @ 40mm) perturbs the
   near-pad W shape (W(5mm)=0.297 vs deep 0.225) -> a small dip/kink ~1us before
   peak and cosine 0.957 vs the deep run's 0.977.  The kink is present in
   store_eps (depth300) and ABSENT in the deep run -> it is a domain-depth
   artifact, NOT caused by the new epsilon code.  A faithful deep (1500) weight
   FDM is ~9 days (infeasible single-resolution); the multires/coarse-to-fine
   pochoir (other checkout) is the proper tool for a full-fidelity deep solve.

** Conclusion
With the corrected comparison convention the current pochoir pipeline (incl. the
new epsilon/permittivity code) AGREES with tred on the physically robust
quantities -- integrated induced charge (=1 eplus) and bipolar waveform shape
(cosine ~0.96) -- and differs by a structural ~2x in the near-pad peak amplitude
that no config/epsilon change removes.  A 1e-6 match to the independent tred
reference is not achievable; documented per Phase-4 rather than fudged.
